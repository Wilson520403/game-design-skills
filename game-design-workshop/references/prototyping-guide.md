# 游戏原型设计实战指南 (Prototyping Guide)

《游戏设计梦工厂》（Game Design Workshop）将原型设计视为验证游戏设计的首要法则。**“早失败、廉价失败（Fail Early, Fail Cheap）”**是贯穿全书的核心座右铭。

---

## 1. 为什么优先进行实体/纸面原型 (Physical Prototyping)？

在写下一行代码、画出一张美术素材之前，绝大多数游戏（包括射击、动作、策略、卡牌）的核心系统都可以且应该通过纸面原型进行验证。

### 实体原型的四大不可替代优势：
1. **极速迭代**: 规则不对？直接拿笔修改纸片上的数字，5秒完成改版。
2. **剥离干扰**: 没有精美美术、炫酷粒子或程序 Bug 掩盖核心玩法的枯燥。
3. **即时动态调整**: 测试过程中如果发现流程阻塞，设计者可充当“人工系统引擎”，实时调整规则继续测试。
4. **低心理包袱**: 扔掉一张草稿纸比推翻程序员写了两周的代码容易得多。

## 2. 实体原型构建工具箱与方法

### 2.1 常用材料准备
- **空白索引卡 / 扑克牌**: 用于制作动作卡、事件卡、手牌、单位卡。
- **多色指示物 / 筹码 / 米宝 (Meeples)**: 代表玩家角色、资源点、生命值、敌人。
- **骰子 (D6, D10, D20)**: 模拟随机性、命中率、伤害浮动范围。
- **方格纸 / 六角格纸 / 白板**: 绘制关卡地形、移动网格、技能树。
- **沙漏 / 手机秒表**: 模拟即时制压力与冷却时间。

### 2.2 如何用纸面原型模拟“非桌面游戏”？
- **动作/射击类**:
  - 用网格地图 + 视野角度模板（纸剪扇形）模拟视线与掩体。
  - 用倒计时限制玩家思考时间（每人每回合仅有 5 秒做出移动和开火决定）。
- **即时战略 / 运营类**:
  - 用筹码池代表矿区，设计者按秒表节奏向玩家发放筹码，测试经济循环与建造升级树的平衡。
- **RPG / 技能构筑**:
  - 用卡牌模拟装备与词条搭配，直接通过对决计算攻防与状态异常（中毒、硬直）的数值感受。

## 3. 数字灰模原型 (Digital Greybox Prototyping)

当游戏机制极其依赖连续操作手感、物理碰撞、空间纵深或复杂动画反馈时，应进入数字灰模原型阶段。

### 3.1 灰模原则
- **白盒/灰盒几何体**: 场景全部使用无贴图的立方体、胶囊体与球体。
- **占位符音效与 UI**: 仅保留最简陋的血条与准星。
- **单一核心玩法聚焦**: 灰模原型必须只验证一个最核心的动作闭环（如跳跃跳台节奏、射击弹道手感、消除手感）。如果在灰模阶段不好玩，无论加多炫酷的特效都不会变好玩。

## 4. 原型设计的“假设验证”方法论 (Hypothesis-Driven Prototyping)

制作任何原型之前，必须清晰写下**本轮原型要验证的具体假设**，切忌无目的地制作庞大系统。

### 假设设计模板：
$$\text{我们认为 [设计点 A]，能够为玩家带来 [体验目标 B]；我们将通过 [测试指标 C] 来判定该假设是否成立。}$$

- **示例 1**:
  - *假设*: 我们认为“玩家在残血时攻击力翻倍的狂暴机制”，能够带来“绝地反击的紧张刺激感”。
  - *验证标准*: 80% 的测试玩家在低血量时会选择主动冒险进攻而非消极躲藏。
- **示例 2**:
  - *假设*: 我们认为“每回合有限的行动点数（AP）分配”，能迫使玩家在“移动”与“蓄力攻击”之间做痛苦权衡。
  - *验证标准*: 玩家在出牌阶段平均思考时间达到 20~30 秒，且不同回合的选择分布均衡。

## 5. 原型迭代工作流 (The Prototyping Loop)

```mermaid
graph TD
    A[明确体验目标 & 提出验证假设] --> B[制作极简原型 (纸面或灰模)]
    B --> C[自我试玩 (排查明显死锁与规则漏洞)]
    C --> D[邀请玩家进行测试 (观察行为与痛点)]
    D --> E[收集数据与评估反馈]
    E -->|假设不成立/规则冗余| F[大幅简化或替换机制]
    E -->|核心好玩/细节需调优| G[微调数值与规则边界]
    F --> B
    G --> B
```
